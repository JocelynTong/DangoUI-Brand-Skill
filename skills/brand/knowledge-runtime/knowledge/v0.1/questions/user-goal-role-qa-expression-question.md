# 怎样让角色、QA 和表现力自己运转，不让用户陪跑？

先问最终交付是不是用户要的真实宿主 Demo，再问内部角色有没有独立 QA，最后问视觉表达是否服务真实任务。内部材料齐全不等于用户目标完成。

角色分工、独立 QA、Expressive 设计都需要，但不要把这些技术判断变成用户问卷。用户只判断感觉与是否应用；系统必须自行发现缺图、遮挡、数据伪造和品牌表达不足。

当前证据来自一次学习前置跑偏，方法仍是候选；回归脚本通过不能冒充视觉验收或跨宿主验证。

独立验收与全新代理是两个判断：局部修复可由原独立 QA 重新检查，但每次都须产生新截图、实际操作和新的验收记录。只有实质改向、规则变化、QA 制作污染或明显漏检才要求新盲审。容量不足由编排者处理，不能转成用户陪跑任务。
