# 三层能力，服务一个用户结果

普通用户提供品牌网址，系统负责学习或复用、设计和专业检查，用户只判断效果与是否应用。角色分工解决谁做，独立 QA 解决有没有做对，Expressive 判断解决是否有品牌表现力；三者不能互相代替。

学习页是内部能力验证，宿主预览才是换肤请求的交付物。学习通过后必须续接原宿主目标；QA 要检查真实宿主内容、交互和渲染效果，不能只检查文件齐全或让用户找缺图、遮挡。

默认给一个有依据的推荐方案，备选可以存在，但不要求用户做专业评审。认可前不修改宿主，认可后沿着准确版本实施，不重开无关三案。

并行只用于独立工作，重复读取和可选探索优先裁掉。没有真实 token 统计就说明不可用；自动返工必须有边界。这是单案例支持的候选方法，不是已经证明跨品牌、跨宿主稳定的结论。

首次验收采用独立盲审。局部修复由合适的原 QA 复验，代理身份保持，验收记录、当前输入绑定、实际截图和操作证据重新生成。复验检查修复区域、受影响的附近区域和已通过的关键交互，不沿用旧 PASS。方向或批准规则实质改变、QA 参与制作或明显漏检时，才要求全新盲审。

QA 接力包只保留页面、素材和来源事实，排除制作脚本、自检解释及夹带旧结论的归档。容量问题保存为可恢复的调度状态；当前机器接入范围为 learn-brand，其余阶段还需分别验证。
