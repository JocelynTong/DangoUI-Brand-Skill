# Expressive moments: source-to-host decision record

This is design knowledge, not a transferable page template. The machine gate checks observable structure; it cannot certify taste. A user rejection overrides a machine PASS and returns to design-host.

## Industry lessons and operational translation

| [IBM Carbon type strategies](https://carbondesignsystem.com/elements/typography/style-strategies/) | Productive controls should be compact; expressive moments can create a contrasting pause or hierarchy, especially on entry, but the two should not be mixed indiscriminately inside one component. | Name the entry/exploration moment and the frequent task separately. Preserve a direct handoff. | H5 contains distinct expressive and productive regions with real host jobs. |
| [IBM Carbon motion](https://carbondesignsystem.com/elements/motion/overview/) | Expressive motion belongs to meaningful transitions; repeated task feedback remains brief. | State a purpose for motion or deliberately use static composition. | Motion is never counted merely because an animation declaration exists. |
| [Google Material 3 Expressive research](https://design.google/library/expressive-material-design-google-research) | Color, shape, size, motion and containment work together to guide attention and group related content; usability must not be sacrificed. | Use more than asset placement or palette change, and carry at least one brand mechanism into real content. | Require a non-asset mechanism in both the entry moment and business content, with a shared source-backed mechanism. |
| [Adobe Spectrum 2](https://s2.spectrum.adobe.com/) | Expression adapts to context and need rather than being one fixed intensity everywhere. | Explain why the host task receives this intensity and where it becomes quiet. | Require a distinct task zone; do not force a universal image-area quota. |
| [Apple design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles) | Delight is purposeful, not decoration; task hierarchy and user agency remain clear. | Keep the primary action discoverable and ask the user whether the proposed feeling is right. | Task region and transition must be present; aesthetic approval remains human. |

## Failure learned from Pokémon backup 4

The fast design-host run `3f2dafe` passed all existing validators in 239.084 seconds, yet the user rejected its expressive result. The recommended Field Search reduced the official scene to a darkened backdrop and returned to ordinary gradient cards. Card Index used an official card as an entry beacon, then switched to a generic white list. The old QA recorded `brandVisualMass: pass` but gave no evidence that the brand language continued into the productive content. The preselector measured distinct signatures and evidence counts, not appeal. This is a **false-positive gate**, not an officially failed aesthetic score.

Corrective rule: an expressive direction must identify a meaningful entry/exploration moment, its functional counterpart, and a visible non-image brand mechanism that continues into business content. Asset area alone never proves this. A candidate may still be quiet when host needs demand it; quiet must be intentional and recognizably source-derived, not a generic page with a logo or hero.

Preventive machine signal: inspect the delivered H5 itself for rendered expressive/productive regions, source-backed mechanism markers, and continuity into real task content. A plan's prose or self-review cannot substitute for these. Machine PASS means **eligible for user visual review**, never **user-approved expressive quality**.

## Failure learned from Pokémon backup 4, H5-only run `42b8131`

The workflow hard-coded two programs and two H5 outputs, so the user could not choose among the requested three directions. Both rendered proposals still followed a scene/header → search/filter → deck-results spine, while their prose described different roles. The H5 CSS introduced broad dark-blue backgrounds, borders and controls that were absent from the plan's frozen semantic color applications. Nearly one radius treatment governed the surface. Both pages also invented named decks and engagement counts even though the host populates those fields through a dynamic API. The expressive marker gate passed, but independent browser QA could not open the `file:` H5 and the run timed out. These are separate failures: insufficient choice, weak composition diversity, unproven color use, unsupported business data and missing visual inspection.

Correction: fast design-host delivers three complete H5 options, never two. Preselection and delivered-H5 gates compare first scene role, content-entry form and result container; each pair must differ across all three. The delivered CSS color literals must resolve to explicitly declared color applications with provenance and scope. Dynamic records need a captured, hash-bound host state; absent that, show an unmistakable neutral schema placeholder rather than plausible but invented data. Shape/radius variation is a brand- and component-role decision, not a universal quota: QA should reject arbitrary repetition or novelty, while the machine gate can only verify declared structural evidence. A static local HTTP preview may be used for inspection; it is not host runtime and creates no screenshot artifact.

## Medium boundary

Design-host deliverables and QA evidence are static H5 plus structured JSON only. Brand assets inside H5 remain allowed. Do not create proposal PNG/JPG, screenshot derivatives, contact sheets or an image-generation stage. Source-learning evidence in learn-brand is a separate input pipeline, not a design-host deliverable.
