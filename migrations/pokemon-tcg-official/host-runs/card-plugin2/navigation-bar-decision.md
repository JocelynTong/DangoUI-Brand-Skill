# 小程序换肤 NavigationBar 决策记录

## 结论

小程序初始化换肤可以、且在沉浸式方向被选中时应当评估直接改变目标页面的 NavigationBar 区域。它不是默认不可触碰的宿主外壳。

本次 `card-plugin2 / pages/plaza/index` 已验证：

- 页面配置可由原生导航切换为 `navigationStyle: 'custom'`。
- 品牌主视觉可以延伸至状态栏和 NavigationBar 背后，形成沉浸式首屏。
- 页面标题、品牌/游戏切换、头像和内容频道切换可以重排到自定义导航区。
- 右上角千岛平台胶囊属于不可覆盖的平台区域；自定义内容必须根据安全区与胶囊占位避让。
- 仅把 Hero 放在原生导航下方会削弱选定的沉浸式布局，不应视为忠实实现。

## 后续流程要求

`apply-host` 在生成首屏候选前必须读取目标页面导航配置，并在 Host Strategy 中明确：

1. `native-preserved`：保留原生导航，适用于效率优先或无沉浸证据的页面。
2. `custom-immersive`：切换为自定义导航，适用于用户选定沉浸式构图且来源品牌证据支持的页面。
3. `custom-contained`：自定义导航但不做全屏背景，用于需要重排标题/操作区但不需要沉浸 Hero 的页面。

选择 `custom-*` 时，Smoke QA 必须验证状态栏安全区、平台胶囊避让、标题/头像/品牌切换可点击性、滚动后的文字可读性，以及不同设备宽度下无重叠。

## 本次复盘意义

NavigationBar 决策必须发生在布局候选阶段，而不是实施末尾补 CSS。否则预览与真实小程序会出现结构漂移，并产生不必要返工。
