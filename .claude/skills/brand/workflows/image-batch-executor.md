# Short-context image batch executor

Own the supplied batch through delivery; the outer conversation does not coordinate intermediate stages. Read task.json and its bound dispatch once. Do not reload the Skill, maintenance chat, other sessions or unrelated source. All complete design and business inputs remain required; short context is not permission to omit them.

For `verify-existing`, generation is forbidden. Do not mutate the source run, old review, images or host. Use the supplied reviewInputs to launch one fresh independent reviewer (`fork_turns: none`). Give it the exact images, bound business/brand inputs, and a new report path under resultDirectory. It must view actual originals, check business controls and required content, brand applicability and expressive differences, and write concrete findings without redrawing. It must not use the old verdict as evidence. Return directly after writing its report; no progress messaging to the outer conversation.

For `continue-authorized-batch`, execute the current preparation or generation dispatch yourself. Do not spawn a separate production coordinator. Use the actual built-in image tool only when allowed; checkpoint successes immediately using provided commands and keep the standard preview available. Do not retry blocked directions automatically. After all attempts, use the returned reviewRequest to delegate independent QA once if appropriate. The reviewer is not the producer. Record its report with the supplied public command and use that command's delivery result; do not repeatedly call status or delivery. Preserve every failure and limitation.

While independent QA is active, do not read its work-in-progress, send acknowledgements, list agents or poll run files. Consume its native completion message. If the runtime requires an explicit wait, use the supported completion wait within the runtime's duration limit here, in this short context—not in the outer long conversation. Report unavoidable waits, not imaginary zero overhead. Do not search logs to measure yourself.

On completion, write result.json under resultDirectory with mode, image paths/hashes, reviewer identity/report path, concrete limitations, generation count, and any waiting/coordination operations actually used. In verify-existing mode, state clearly that this is a new bounded review of existing images, not a generation run, not a new official PASS, and not proof of end-to-end token savings. Final reply: result path, actual image count, selection-relevant findings. Send only this final result to the parent.
