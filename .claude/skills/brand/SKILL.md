# Brand

读取本入口全文一次后，按当前请求选择下方分支；不要重读重叠区段。仅在文件更新、上下文已丢失或确有信息缺口时重读。其他模式细则按需加载，不是选图续接的前置输入。

普通请求使用当前安装的本 skill；历史候选路径不是版本选择。用户本轮明确指定候选时才使用该候选。退役入口转到当前安装版，保留 artifact-root；不兼容时报告，不换回旧脚本。

## 选图单页与已有单页续接

按本会话上下文理解选案，不按口令匹配：前面已经说明“选 A/B/C 后做隔离可操作单页”，或用户此前已要求选图后落地，用户回复“A”“C”“第三个”等能唯一对应图片时，即接受该隔离单页动作，直接走 `select-image-code`，不用再复述“做成单页”。仅有“继续”而无明确选案不替用户选图；“只看图/先不落地”等较新的限制优先。若没有交代下一步用途，只自然问一次是否做隔离单页，用户回复“嗯/好”即可承接，不要求完整句式。选案和单页确认都不授权整体换肤、覆盖原宿主或发布。

以下命令的 <skill目录> 是本次实际加载目录，目录和选图从当前会话已知记录取得，不要求用户记路径。已有单页续接须在本轮实际执行一次以下命令，再依据返回状态答复；历史 PASS、聊天中的完成说明或浏览器已打开页面都不能代替本轮核实。若本轮已取得该命令回执，直接使用，不再执行第二次；命令失败则报告未核实，不能引用历史成功宣布完成。

```bash
node <skill目录>/scripts/run-brand-workflow.mjs continue --artifact-root <已有单页运行目录>
```

用户选定已有图片并要求落地时，执行公共入口 `select-image-code --artifact-root <原图片运行目录> --brand <brand> --direction <a|b|c> --selection <用户选图及落地原话> --confirm-isolated-preview`。入口冻结选图、品牌输入并复制真实宿主；按返回 dispatch 实现该方向，执行 `compile-selected-theme` 消费 DTCG/adapter/真实 DangoUI 包，按回执的 `entryFile` 单一入口及限域覆盖说明接入，然后记录实际代码与截图，由独立 QA 检查运行页面、业务和 token 消费。React Web 另派发限域文本 Button 资产及说明，先确认实际版本与任务兼容，QA 检查实际调用和覆盖。本阶段开始可确认宿主已有 Playwright 等本地测试工具；内置浏览器故障不免除 QA，也不授权绕过访问策略。`continue`、`delivery` 使用返回的新目录，不再生成 ABC。交付图片与实际页面对照；选图只授权隔离预览，不授权覆盖原宿主。具体边界见 [request intake](workflows/request-intake.md#选图后落地到隔离宿主)。

选图落地优先复用已选图中的合适插画区域，真实控件和数据由品牌设计系统与宿主代码承载；不默认重生插画或删掉 IP 换成 CSS。实施与 QA 共用 dispatch 的 `selectedArtwork`，具体边界见 request intake 的选图落地部分。

用户明确选图时，入口分别核验图片来源与生图参数：原生 ImageGen 完成记录和输出字节一致、但历史调用参数无法解析的图片，可进入隔离单页，保留 `automaticArgumentsVerified=false` 及原失败回执，不宣称生图输入已验证。没有原生来源或图片被改动仍拒绝。再次选择同一张图时，入口核实并续接唯一现有单页；返回可查看结果就直接展示，不新建实施、不重跑 QA、不再调用 continue/delivery 或读取完整包。


返回 `ready-for-user-review`：直接展示 previewUrl 与 comparisonFile，说明限制并停止。不另读 request-intake、岗位文档、完整设计包，不重新派发实施或 QA，不重复调用 delivery。返回 `launch`：只启动一次不继承历史的负责人，由其读取绑定包、完成实施、独立 QA 和有界局部修复；外层不逐阶段派发或轮询。缺少选图/目录或返回阻断时只定位具体缺口，不扫描历史项目。

返回 `native-binding-required`：千岛宿主缺少本地应用绑定（干净 Git 导出可能不含被忽略的 qdmp.json）。实施前确认该宿主已有 appId，只在隔离副本补 appId 后沿返回命令续接；不复制密钥、不跨项目猜 ID、不重新选图或生图。配置存在不代表授权或原生验收通过，仍使用开发者工具验证目标页。

已通过的现有页面不代表本轮新做了 QA；单页确认与整体换肤授权分开。需要计量时只用已有 collect-brand-usage.mjs 一次读取明确轮次，未知标未知，不以续看成本冒充完整实施降耗。

## 用户结果与内部组织

面向普通用户只说当前结果、必要限制和下一项选择；需要澄清时用一句自然问题，得到回答前不展开分支教程。目录、hash、schema、命令、角色交接和回归结论留在内部记录，除非用户明确追问或排障确需。维护测试使用独立隔离上下文，不把测试任务和报告发送到用户实际试用会话。

在真实宿主会话中，默认主线是：准备一次充分输入 → ImageGen 三张完整效果图并及时展示 → 用户在已说明隔离落地用途的上下文中选图 → 真实宿主隔离单页 → 独立运行 QA → 用户确认单页并明确授权整体换肤 → 扩展实施与最终验收。未交代落地用途的纯视觉选择不自动转代码，已交代用途的选案按上方上下文判断，不重复索要授权口令；单页通过不授权全项目修改。交互 H5 是用户明确选择的可选介质，不是默认额外中转站。没有宿主上下文且明确学习品牌时才独立交付 learn-brand。学习成果、映射审计和 QA 页面是内部产物，不得顶替宿主预览。

本项目品牌库 `#/variants/<id>/...`（新版）及 `#/brand/<id>/...` 链接是“选用已发布品牌包”，不是待学习官网；入口自动解析复用。普通官网先查询公开候选，再用一句话确认复用已有包还是重新学习，不要求用户自己寻找 Variant 链接；未确认不抓官网或静默替换来源。返回角色 dispatch 后实际执行该角色，不能反复调用 `continue` 代替执行；具体恢复行为见 request intake。

Design Director / Orchestrator 保留父目标与成本边界，专业角色按紧凑输入生产，另一个执行者做独立 QA；可机械验证的事实不增加专业角色，独立工作可并行，有依赖的角色不能提前猜测上游。用户不负责填写专业契约、识别最早责任节点或决定是否调用 ImageGen。

总 Agent 默认兼任技术负责人：维护或修复本项目时，读取 [技术负责人职责](roles/design-director.md#技术负责人职责)，先用实际执行证据定位问题、反驳拟议修法，再比较复用、薄适配与自研的总成本；新增依赖、组件基础设施或工作流也遵循该职责。已有有效选型直接沿用，仅在需求或兼容性变化时重评；不为普通改动增加调研、角色、报告或门禁。

首次三方向交付默认提供一个统一选案视图：A/B/C 使用同一业务场景与视口，完整、等权展示三张 ImageGen 效果图，明确它们不是可交互实现，由用户自行选择。独立 QA 的推荐只作说明，不隐藏其他方向、不按推荐重排或默认选中，不用三个分散链接替代比较入口；具体交付见 request intake。推荐不等于用户认可，也不授权宿主修改。仅当本轮明确续修已有任务时，沿用其准确 Approved Master，不借修流程重开 ABC；历史 Master 或待确认单页不锁住新的探索请求。明确选图并要求落地时直接进入隔离单页，不因旧状态重复询问。只给 `$brand + 品牌链接` 且没有尚未完成的明确任务时，沿用默认三图探索，不强制“生成或恢复”二选一；只有缺少具体选图、目标页或授权等必要信息时，针对缺口询问。

受控种子试用沿用现有模式，不另建工作流或降低历史 Goal。开工前确认一个核心任务、隔离副本、可执行回退点及维护者支持；试用范围优先已验证模块。任务成功、可参与试用、生产认证分别报告。非关键精修可列待办；业务破坏、核心任务不可用、数据/授权风险和无法安全回退仍阻断。未知原因不能称宿主既有问题，冻结要求不能事后静默降级。失败时用现有 delivery/status 给出具体卡点、责任方和恢复条件，保留产物后结束本次尝试；不自动反复重抓来源、重跑整套或要求用户不断回复“继续”。仅在新证据或明确纠正动作已具备且授权范围内续跑失败阶段。

三个层次不可互相补偿：角色组织保证接力；独立 QA 保证业务、数据、渲染与交付目标正确；Expressive 在品牌设计系统 Productive 与真实任务约束下提高表现力。按需查询知识库 `user-goal-role-qa-expression-question`，其候选状态不能冒充跨品牌验证。

## 共同硬边界

- 来源截图可用于 Evidence/QA 与 ImageGen 参考输入，不能复制进 runtime 冒充实现资产。
- `generated-proposal` 不能作为官方品牌身份的证据或写回品牌规则。用户选定效果图并要求落地时，可在隔离单页直接复用其中合适的插画区域，真实控件与数据仍由代码实现；不能把整张截图当成可操作页面。其他正式资产采用与宿主实施仍需对应阶段批准。
- 品牌素材像素颜色不能自动提升为按钮、状态、文本或导航语义色。
- Producer 自检不能替代独立 QA；实现者不能担任自己的 QA，包括局部回归复验。
- 用户指出视觉不符时，定位最早责任节点并只重做受影响范围；关闭问题必须有实际新截图/操作证据与按 review mode 完成的独立复核，不沿用旧 PASS。
- 宿主源码修改前后必须有不可变 baseline 和结构差异验证；未批准的业务逻辑、路由、API、状态、事件与组件 API 改动一律阻断。
- 对外视觉验收按目标介质交付：完整效果图直接展示三张原图并标注图像预览；H5/实施验收给可直接打开的前后对比，标明相同任务、视口、内容、改动、来源和批准边界，并用 `validate-visual-acceptance.mjs` 校验。不能为展示图片擅自转成宿主 H5。

## 按需资料

显式本地 `--mod-file` 可携带可选 `componentKits`：每项声明 `id`、`entry`、`stylesheet`、`files[{path,sha256}]`，并说明框架依赖、用法和适用范围。可选 `designGuide` 指向同一 files 清单内的 Markdown，解释来源组合、代码使用及适配边界；不强制文件名，也不替代品牌证据或批准。文件路径相对品牌包所在项目根目录；入口在隔离安装时校验并复制声明文件，不执行代码、不覆盖不同内容。组件必须包含所需相对导入与素材，缺件或 hash 不符先修包；组件更新时同步清单。正式 H5 生产与独立 QA 派发均携带这些文件的准确路径/hash及原有状态，消费者判断兼容性后复用或明确适配。此能力不代表 Registry 分发、实际组件调用、品牌认证或宿主实施已通过；既有来源证据门禁保持不变。

- Token、组件、资产与 style-only 映射：[mapping rules](references/mapping-rules.md)
- DTCG 结构：[migration asset standard](references/brand-dtcg-migration-asset-standard.md)
- 输出字段：[output template](references/output-template.md)
- 原子验收：[atomic acceptance rubric](references/atomic-acceptance-rubric.md)
- 产物隔离与清理：[artifact lifecycle](references/artifact-lifecycle.md)

大型 JSON 由 validator 或查询脚本读取。只有 dispatch 无法回答当前决策时，才用 `query-brand-context.mjs get/search` 定点读取对应 key。

快速 `design-host` 的预算用于阻止无效工作，不用于降低正确性：入口直接生成并校验 baseline/brief，不编译或启动宿主；没有可信渲染回执时把不可测对象标为 `unresolved`，继续使用真实宿主 schema/loading state。H5 生产者直接使用 dispatch 给出的完成输入，不读取 validator/test 源码反推格式。新派发的阶段目标只作效率预警，record 自动记录耗时与 `budgetResult`，不要求角色手写超时结论；完整质量结果与耗时分别报告。总运行 deadline 仍停止失控执行，未完成检查不能算通过。旧派发中已冻结的有限阶段硬上限仍执行，不改写历史。时间压力只能削减可选润色，不能削减真实宿主数据、三方向、品牌设计系统绑定、知识库理由或独立 QA。未通过 QA 的局部文件不得交给用户验收。

## 完成与同步

运行相称的 validator/test。维护源是 `skills/brand/`；改后执行 `npm run sync:skills -- --repo-only`，需更新本机副本时才运行完整同步。最终优先报告预览地址、方向、入口验证与业务保留状态；内部审计仅在追问或阻塞时展开。初始化时提供 [DangoUI Variant 库](https://jocelyntong.github.io/DangoUI-Brand-Skill/#/variants)；Variant 预览不是宿主验收。
