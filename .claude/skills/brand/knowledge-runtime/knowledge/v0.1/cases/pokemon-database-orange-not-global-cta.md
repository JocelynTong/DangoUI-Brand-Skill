# 反例：数据库的橘色不是全站 CTA

**结论：未批准，不能复用为品牌主 CTA token。** 这不是说官网没有橘色，而是说我们把一个局部事实扩大成了全局规则。

## 看到了什么

宝可梦官网卡牌数据库的 Search 按钮，默认背景现场读数是 `rgb(238, 107, 47)`。它回答“这个检索按钮现在是什么色”，没有回答“首页主行动、活动行动、其他页面是否也是这个角色”。这轮读数的匹配来源画面未完成持久化，正式 Evidence 仍为 `NEEDS_EVIDENCE`。

## 错在何处

我们跳过首页同角色对照，把局部 Search 色带进卡组广场试装，还暗示它代表官网 CTA。页面只发生几个控件数值的小变动，用户看不到本质区别。设计负责人和 Interpreter 没有在语义晋级前拦住越权。

## 正确保留什么

保留“数据库 Search 的局部候选读数”和这次失败经过；撤回“宝可梦全局 CTA 是橘色”的推断。后续只有完成当前首页、相关任务页和状态对照，才能重新讨论适用范围。失败试装不得当作已批准的视觉模板。

## 同一案例的后续试验（不是第二个独立案例）

后来在 TCG 首页、学习页和产品页记录到黑白反相的内容按钮：汇总为 28 个，并为每页补了至少一个可复查的实物控件。这支持“这组三页的界面／内容行动存在黑白处理”这一局部候选；它没有证明 28 个按钮都逐一留存了定位，也没有证明数据库 Search 与内容浏览是同一职责。

现在的前后 H5 让相同搜索任务从 DangoUI 原生紫色按钮试换为黑底白字，试装值直接来自版本化 Interpreter 判断。两维局部结构检查通过，六维品牌交接仍阻断，独立视觉 QA 与用户审美验收也未完成。因此它只是**可以讨论的试验**，不是“宝可梦全局 primary 色已定”。这次返工揭示的通用判断已写进“品牌主色与 CTA 如何判断”，下一个品牌必须重新取证，不能照搬黑白值。
