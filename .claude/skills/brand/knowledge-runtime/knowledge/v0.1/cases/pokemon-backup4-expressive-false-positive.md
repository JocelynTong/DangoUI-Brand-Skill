# 反例：首屏有品牌，不等于任务里有品牌

**结果：机器协议通过，用户视觉不满意；不能记为 expressive 获批。** 本案例记录的是设计判断和门禁的误判，不是可复制的宝可梦页面模板。

## 决策档案，不是假装当时已经想清楚

这是事后复盘。旧记录没有设计师完整的选案理由，也没有用户批准；不能把今天的解释冒充当时的决策。已知当时预选器推荐 Field Search，但它主要比较结构签名和证据数量，没有判出画面是否真的打动人。

面对这份 case，专家要问：在“反复搜索卡组”的任务里，品牌氛围能否从入口延续到真实结果，同时不挤掉第一个搜索动作？Field Search 的入口有官方场景，任务区却退回普通渐变卡；Card Index 的入口有官方卡牌，后续却退回通用白列表。两案各有第一眼，但都缺少入口到任务的视觉交接。因此复盘后的决定是**两案都不批准为可复用配方**，保留搜索任务骨架，退回构图设计。

原先的隐含判断是“官方素材占比够、结构门禁通过，expressive 就成立”。用户反馈推翻了这一点。修订成候选规则：遮住 Logo 和主图后，真实任务内容里仍须看得见有来源的非图片品牌机制，而且首动作不能被遮挡。它只是一条由负例提出的假设，还没有被另一品牌或宿主正向验证。

## 当时如何判断，漏看了什么

宝可梦备份 4 的一轮 fast design-host 在 239.084 秒内完成并被机器标为 SLA PASS。检查覆盖了素材载入、溢出、品牌画面占比、方案结构差异和任务清晰度。它们证明页面可以交给人看，不能证明品牌表达有说服力。

Field Search 把官方场景压成深色背景后，真实任务内容又回到普通渐变卡片；Card Index 用官方卡牌作入口，后续是通用白色列表。设计时把“入口用了官方素材”和“品牌机制贯穿任务”混成了一项。结果是 expressive 停在第一眼，productive 区虽然可操作，却失去品牌识别。

## 这次抽象出什么判断

对这类需要反复搜索和浏览的宿主，不是简单把更多画面面积交给 expressive，也不是要求所有控件都夸张。设计负责人应先比较第一动作和首屏可见内容，再要求来源可追溯的字体、形状、材质、空间节奏或动效机制至少有一种延续到真实结果。遮住 Logo 与主图后如果只剩通用列表，就要重新设计交接，而不是再加一张大图。

## 下次怎样验证

候选方向同时提交入口与真实任务区，在同一宿主内容和视口下比较首动作、结果可见度与品牌连续性。脚本只拦缺来源、缺任务区、缺延续机制；独立视觉 QA 和用户仍有权否定美感。若下一次跨宿主复验仍有效，才考虑晋级为更稳定的方法；目前保持候选。
