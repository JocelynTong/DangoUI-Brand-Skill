# 一个颜色何时才有资格成为 token？

先问“它做什么”，再问“它是什么颜色”。相同的橘色可能分别用于搜索、提醒或活动；用途不同就不能合并。不同颜色也可能都是各自场景里的首要行动，不能机械地投票选出现次数最多的值。

## 比较办法

- 对拟命名的角色列出相关核心页面，逐页记录相同职责的控件及默认、悬停、焦点等实际观察到的状态。
- 每页至少留一个能重新找到的实物按钮：官网地址、元素定位、所在区域和实际绘制的底色／字色。另列“只汇总计数、未逐控件复核”的数量，不把总数冒充全部实物证明。
- 一行没有证据就写“未观察”，不要拿另一页的控件代填。
- 分开写一致、冲突与解释。活动 CTA、数据库 Search 和普通提交按钮可能本来就有不同范围。
- 只批准证据能覆盖的最窄范围：全局、场景、组件、单一状态，或暂不映射。

## 放行判断

要成为全局 token，核心页面不能未比对，冲突不能悬而不决。页面专用样式可以留在局部配方，但不能借“来源官网”四个字进入 DangoUI 全局变量。脚本检查记录是否齐全；设计负责人判断语义解释是否合理。

## 这次反例

宝可梦卡牌数据库 Search 按钮的橘色只能支持局部控件观察。首页冠军赛 CTA 的历史记录又是深色默认、金色悬停且限定在区块内。它们不能推出一个通用的宝可梦 CTA 颜色。
