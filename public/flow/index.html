宿主流程：四个平级角色，一条产物链

角色有专业分工，没有层层负责人。先后关系是输入依赖，不是组织上下级。

前置输入：品牌学习产物 + 真实宿主需求

learn-brand 负责来源学习。宿主流程在 design-host 中完成分析与设计，用户选定后进入 apply-host 实现。独立验收可在候选试片和最终实现两个时刻介入，不必等到最后。

1

宿主分析

哪里值得表达、哪里必须高效

输入
真实任务、路由、数据状态、品牌输入
交付
任务与保护边界、表达机会、空间预算
2

视觉设计

采用哪种视觉机制及其取舍

输入
宿主分析结论、来源依据、相关决策
交付
候选方向、动态可行性试片、选定视觉契约
3

宿主实现

在冻结目标内选择实现方法

输入
已选择方向、不可变基线、实际数据与平台约束
交付
真实宿主实现、运行证据、已知差异
4

独立验收

证据是否支持视觉与业务结论

输入
选定目标、运行产物、保护边界
交付
通过或定位到责任节点的缺陷
交接：宿主分析 → 视觉设计 → 用户选定 → 宿主实现 → 独立验收

没有 expressive 需求时不强制生图。有需求时，视觉设计选择代码、既有素材或生图，并在冻结前证明动态可行性。实现阶段不能自行换方向。

失败直接回到对应专业：任务判断 → 分析；视觉方案 → 设计；还原与行为 → 实现；证据不足 → 补验收。

编排是公共服务，不是第五层负责人

仅负责派发、记录状态、冻结已确认产物和回退。生图、拆图、渲染、脚本是工具，不是下级组织。执行入口保留既有角色 ID 以兼容旧记录。

共享决策库：通用问题，不是案例配方

每个角色在关键判断时：检索问题 → 比较上下文与反例 → 选择解法并说明理由 → 执行与观察 → 回写案例。

  1. 设计依据：多个参考如何保持一致，而不是“选哪个蓝色”？
  2. 空间关系：动态内容如何融入环境，而不是“一定分三层”？
  3. 内容适配：有限素材如何适应无限列表，而不是“一律渐变”？
  4. 运行一致性：哪些关系必须在状态变化后保持，而不是“所有卡都必须变”？
案例观察 → 候选原则 → 跨情境验证 → 有边界的共识 → 反例修订

共识包括适用条件、可选解法、取舍与失败信号。通用表述不等于通用证明；现有案例仍为候选。自动校验不能替代视觉判断。
