02 · BRAND INTERPRETER / 品牌语义判断

拿到频次后，怎么选候选？

Evidence 已交来逐页数量。Interpreter 不再重新采色，而是把频次与页面来源、按钮职责和背景一起比较，决定哪个先试、哪个只限局部、哪些还不能成为全局 token。

判断有候选 · 无全局批准
一句话：这组 TCG 页面的界面主导色系，已经可以判断为黑与白。这 28 个样本里，黑底白字 20 个（约 71%），白底黑字 8 个（约 29%）；3 页抽样的 28 个内容按钮全部采用黑白反转；这足以形成网站界面色系的明确候选，不等于所有宝可梦业务的品牌色，更不自动批准某个 DangoUI 全局 token。
Evidence 交来的频次Interpreter 如何解释交给下游的决定
多色宝可梦标志3 / 3 个 TCG 页面都有；跨页稳定。
身份优先级高，但用途不同跨页稳定说明它是强身份线索；多色标志不能直接抽出一个按钮底色。
不能交全局色值多色标志 ≠ 界面色系未定多色 Logo 说明品牌标志不能压成一个十六进制色值；它不妨碍依据跨页按钮证据，另行判断网站界面以黑白为主。
黑底白字白底黑字内容按钮：20 / 28 黑（约 71%）；8 / 28 白（约 29%）。
黑白反转跨页稳定黑底白字出现在 3 个页面，白底黑字用于需要反相的场景；28 个内容按钮无一使用饱和色底。另记的 9 个页脚工具按钮也都是黑底白字。黑白是这组 TCG 页面的界面与行动主导色系候选；但按钮任务混合，不能直接推为搜索按钮的全局值。
界面色系候选 · token 尚未批准主导界面色系：#000000 / #FFFFFF浅色面用黑底白字、深色面用白底黑字；浅色检索壳先试黑色。要写入全局 DangoUI 主按钮 token，仍须补搜索同职责和 hover/focus、对比度、独立视觉 QA。
橘色 Search2 个数据库搜索提交按钮
数量少，且是另一种任务2 个都属于数据库 Search；不能拿它们与 28 个 TCG 内容按钮混成一个投票池，更不能由“也是按钮”推导全站主行动色。
只留局部观察不得升为全局 CTA这条申请已阻断；DangoUI 映射不得拿橘色当宝可梦全站按钮色。
这一步确实用了 Evidence 的频次： 黑白覆盖 28/28 个已数内容按钮，因此可以命名为这组 TCG 页面的界面主导色系；黑色是浅色面的先试分支，白色是反相分支。橘色只在数据库 Search。此前单页静态 CSS 曾提示黑金氛围，但那不是跨页可见按钮统计，不能用来否定黑白行动系统；金色的具体角色仍待单独核实。
