品牌身份、界面色系与行动色的分项比较

  • 分开品牌身份、界面色系、主要行动色和目标 token。多色标志不必压成一个色值，也不代表界面色系无法判断。
  • 优先比较身份入口与相关核心页。每条观察记录区域、职责、背景和状态；行动色只比较同职责控件，读取实际绘制层的底色与字色。
  • CSS 声明次数、可见控件、Logo 像素和宣传素材属于不同证据池；隐藏轮播副本不计可见按钮，工具按钮不混入内容 CTA 分母。保留代表控件定位，并明确汇总中未逐项举证的数量。
  • 先解释一致、反相和局部例外，再考虑同职责频次；冲突未解决时不宣称全局。颜色只是观察，语义与范围需另作判断。
  • 分别交付身份、界面色系、行动色、例外与缺口，核对目标 token 状态、对比度和真实渲染。允许界面色系有候选、全局按钮暂不映射。
  • 局部两维检查与完整品牌检查分开；目标、Evidence 和解释产物版本一致，旧 PASS 不继承。候选试装变色只证明生效，不自动批准视觉或全局语义。

通用判定方法pilot-candidate

设计资产的职责、证据与复用范围审查

  • 明确对象是什么、在来源中做什么、拟在目标里做什么，再比较职责与情境是否相符。
  • Token 检查语义、状态和对比度；素材检查来源、使用权、主体和裁切；组件检查行为与 API；构图检查层级、任务路径和响应式关系。
  • 区分观察范围、申请范围与批准范围，记录冲突、证据缺口和例外，不能从局部出现直接推向全局复用。
  • 专业角色提供判断依据，独立验收检查真实落地；记录审阅人、来源版本和可用范围。只有已批准且范围匹配的资产可供正式下游消费。
设计资产决策 · tokenblocked · 仅限 observation

数据库 Search 橘色的全局晋级已阻断

申请把数据库 Search 默认态 rgb(238, 107, 47) 作为全局 CTA 的依据不足，批准范围只停在局部观察。

补看的官网首页探索按钮为白色，数据库 Search 为橘色，教学页入口为白色描边；这些控件职责不同，且未覆盖完整交互状态，不能推导统一主行动色。

重新申请需补同职责跨页状态、语义、对比度及目标映射证据，再经独立检查。来源记录保存在同名结构化判定中。
