DangoUI Brand Skill

从品牌学习到稳定换肤

Skill 把品牌证据转化为可复用的设计规则和 DangoUI 实现，并用四个红色闭环阻断来源、映射、效果和业务层面的漂移。

01 · 输入

品牌官网 / 截图 / Figma / DTCG

收集可追溯的视觉来源，而不是仅凭印象模仿。

02 · 路由

新品牌还是存量品牌？

新增流程建立档案；更新流程先继承历史学习成果。

闭环一

来源不漂移

保存学习网站本体、版本与哈希；存量更新不丢证据。

闭环二

映射不漂移

只映射 DangoUI 真实能力；缺失能力必须显式登记。

04 · 规则化

提炼品牌语言

把证据解释为可用与禁用规则，而非复制单个页面。

03 · 学习

提取可验证证据

颜色、字体、资产、构图、动效与响应式行为。

05 · 能力判断

DangoUI 能否承载？

能：生成 Brand MOD；不能：记录 Capability Gap 后再实现。

06 · 生成

Style Pack + Demo

由证据、规则和组件映射共同驱动可预览页面。

闭环三

效果不漂移

同时通过证据还原、结构还原与生成迁移三类验证。

07 · 门禁

三类验证是否通过？

未通过就退回证据、映射或实现责任节点继续修正。

闭环四

业务不漂移

换肤时保留路由、数据、组件 API 与关键交互契约。

08 · 应用

应用到宿主项目

Web 先行，并为 Taro、小程序与更多终端保留同一契约。

09 · 真机验证

浏览器 / 响应式 / 设备

检查桌面、移动端尺寸、触控与真实运行结果。

10 · 交付

发布可复用的品牌资产

沉淀来源、Style Pack、Demo、验证状态与版本记录，供后续项目复用。

红色：直接影响换肤成功率的四个闭环 紫色：流程分支与质量门禁

四个闭环不承诺 100% 自动成功；它们的作用是让不可验证的结果不能直接交付，并把问题退回到明确的责任节点。
